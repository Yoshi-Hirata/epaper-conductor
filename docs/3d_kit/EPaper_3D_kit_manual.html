E-paper 3D キット

AZ 27SS の衣装の鱗(電子ペーパー)の色の変化を、Blender の 3D モデルで再現するための説明書 ― 2026-10-22 版

このキットは、ショーを操作する PC(Conductor)が書き出す 3D 用 JSON と、それを Blender で読み込む Python スクリプトのセットです。スクリプトを実行すると、モデルの各鱗に、本番の画面と同じ色の変化 (書き換えの波と、書き換え中のチラつきを含む)がキーフレームとして入ります。 受け取る側で計算することはなく、鱗のオブジェクトに決まった名前を付けておくことだけが必要です。

2. 全体の流れ

① ショーの PCConductor の Timeline で Export for 3D simulator… を押し、JSON を書き出す
② 受け渡しJSON(と必要なら音源の MP3)を 3D 担当へ渡す
③ Blenderスクリプトで JSON を読み込むと、全鱗にキーフレームが入る

演出が更新されたら、①〜③を繰り返します。スクリプトを再実行すると、前回のキーは置き換わります。

3. 動作環境

  • Blender 3.6 〜 5.x。4.4 以降の新しいアニメーションの仕組み(スロット付きアクション)と、それ以前の仕組みの両方に対応
  • 追加のアドオンやライブラリは不要(Blender に入っている Python だけで動く)

4. モデルの準備(鱗の名前)

鱗は、本番の配線ファイルの ラベルで識別します。各鱗のオブジェクトに、このラベルと同じ名前を付けてください。

ラベルの例意味
017-01基板 17 番のソケット 1 番につながっている鱗(基板番号は 3 桁、ソケットは 2 桁)

  • 鱗は 1 枚 = 1 オブジェクトにしてください(色をオブジェクトごとに付けるため)。メッシュの共有(リンク複製)は問題ありません

5. 実行のしかた

A. Blender の画面から

  1. モデルの .blend を開き、Scripting タブへ
  2. テキストエディタで import_epaper_3d.py を開く
  3. 先頭の設定 JSON_PATH = r"…" に、書き出した JSON の場所を書く
  4. Run Script(▶)を押す。結果はシステムコンソール(Window → Toggle System Console)に出る
[epaper-3d] {'scales keyed': 1217, 'keys': 270928, 'missing objects': 0,
             'show 0:00 at frame': 241.0, 'frames': (1, 19891), 'fps': 30.0}

B. コマンドラインから

blender model.blend --python import_epaper_3d.py -- show-3d.json

-- のあとに JSON の場所を書きます(JSON_PATH より優先)。保存まで自動にしたい場合は、 --background を付け、最後に bpy.ops.wm.save_mainfile() を呼ぶ 1 行を足してください。

6. 設定項目

スクリプト先頭の settings の部分を書き換えます。

項目既定意味
JSON_PATH空読み込む JSON の場所
ITEMSNone読み込む品番。None は全部。例:["AZ271SD1307"]
INCLUDE_PRESETTrue開始前のプリセット(マイナスの時刻)からフレームを並べる。False なら 0:00 が開始フレーム
NULL_COLOR#808080ショーの色が付いていない鱗の色(最初の色が付くまで、など)
ASSIGN_MATERIALFalseTrue にすると、全部の鱗に共通マテリアル「EPaper Scale」を付ける(既存のマテリアルは外れる)
EMISSION0.00 より大きいと、その強さで鱗の色を発光させる(実物の電子ペーパーは光らない)
MUSIC_PATH空音源のファイル。指定すると、0:00 の位置にサウンドストリップを置く
SNAP_TO_FRAMESFalseTrue で 1 フレームに 1 キーへまとめる(軽くなるが、1 フレームより細かいチラつきは消える)
ACTION_PREFIX"EPaper "作るアクションの名前の頭。再実行のときはこの名前で置き換える

7. 見え方(色・マテリアル)

  • 色はオブジェクトの色(オブジェクトプロパティ → ビューポート表示 → カラー、obj.color)に、 補間なし(Constant)で打ちます。マテリアルを鱗ごとに複製しないので、8,000 枚でも 1 つのマテリアルで済みます
  • ビューポート:Solid 表示のシェーディング設定で Color を Object にすると、すぐに見えます
  • レンダー:スクリプトが作るマテリアル「EPaper Scale」は、Object Info ノードの Color を Base Color につないだものです。 手持ちのマテリアルを使う場合は、Object Info → Color をつないでください
  • JSON の色(#rrggbb)は sRGB です。スクリプトがリニアに変換して入れるので、 カラーマネジメントの View Transform を Standard にすると、本番の画面の色とそろいます(Filmic / AgX では色味が変わります)
補間は必ず Constant のままにしてください。 キーの間をなめらかにつなぐと、色が混ざって本番とは別の見え方になります。グラフエディタで補間を変えないでください。

8. 時間とフレーム

  • JSON の時刻はショーの時計(秒、0 = START、ミリ秒単位)。シーンの fps(fps / fps_base)でフレームに直します
  • 開始前のプリセットはマイナスの時刻から始まります(今のデータでは −8 秒)。INCLUDE_PRESET = True のとき、 その最初のキーがシーンの開始フレームになり、0:00 のフレームは実行結果の show 0:00 at frame に出ます
  • シーンの終了フレームは、ショーの長さ(duration)に合わせて自動で設定します
  • キーは書き出しどおりの時刻(小数のフレーム)に打つので、レンダーの fps を変えても時刻はずれません
  • 音源は JSON に入っていません(名前だけ)。ショー担当から MP3 を別に受け取り、MUSIC_PATH に指定してください

9. 書き出し直したとき

  • 新しい JSON でスクリプトを再実行すれば、前回のキー(アクション EPaper <ラベル>)は置き換わります
  • 鱗に手でつけたほかのアニメーションがある場合、そのオブジェクトのアクションは差し替わるので注意してください

12. JSON の中身(要点)

詳しくは EXPORT_3D_FORMAT.md。スクリプトを使う限り、中身を意識する必要はありません。

{
  "format": "epaper-3d-timeline", "version": 1,
  "duration": 655.0,                      // ショーの長さ(秒)
  "music": {"name": "….mp3"},             // 音源は名前だけ
  "interpolation": "constant",
  "colors": ["#3a2f5a", "#2b2a4e", …],    // キーが参照する色の表
  "items": {
    "AZ271SD1307": {
      "look": "28",
      "scales": [{"label": "033-01", "side": "front", "row": 14, "col": 10}, …],
      "cues":   [{"at": 10.0, "design": "…csv", "label": "案-G", "partial": false}, …],
      "keys":   {"033-01": [[-7.865, 0], [-7.615, 1], …]}   // [時刻(秒), colors の番号 or null]
    }, …
  }
}
  • keys が鱗ごとの色の変化のすべて。各キーの色を、次のキーまで保持します
  • null は「ショーの色が付いていない」状態(スクリプトでは NULL_COLOR)
  • cues は参考情報(どの時刻にどのデザインへ変わるか)。字幕やタイムライン表示に使えます
  • 書き換え中の鱗は、暗転 → いろいろな色のチラつき → 目標の色に寄っていく → 確定、を 0.25 秒程度の刻みで変化します。 これも全部キーとして入っていて、本番の Conductor の画面と 50 ms 刻みで一致することを確認済みです
