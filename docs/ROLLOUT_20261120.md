## 1. 1 台目だけ(確認してから先へ)

1. **GIT PULL**(メニュー末尾)→ KEY1 で `git pull --ff-only` → `UPDATED` → KEY1 で UI 再起動(約 15 秒)。
   `UP TO DATE` なら前の pull で済み。`FAILED`(fast-forward 不可・ネットワーク)なら SSH で `git pull`
2. 30 秒何も押さないと LCD が消えることを確認(押すと点灯だけ)
3. SSH で `grep -E -- '--firmware|--blank-after' /etc/default/epaper-ui`。**何も出なければ正常**。
   `--firmware` が出たら外す(既定の画像が使われない)、`--blank-after 0` が出たら消灯しない
   (意図したものか確認。なければ外して再起動)
4. **UPDATE FW** を 1 枚に: 確認画面が **`< 2/2 >`**、ファイル名が `mcb_pinks_0a-purple_0c-red.bin` と
   最後まで見えること。`< 1/2 >`(`MCB_16_0923.bin`)なら RIGHT で `2/2` へ。`2/2` が出ない = pull 未反映
5. 書き込みは約 1 分。ログの `No ACK to 0x28 -> rebooting` は**正常な成功の印**。基板が黙ったままなら
   機体が USB を回して復旧を試みる(待つ)。`FAILED` は KEY1 でやり直し
6. **FW VERSION**: その基板の行が**緑**で `FW_261119F`(`bundled: FW_261119F`)。緑でなければ書けていない
7. **DEMO の 16COLORS**: 16 色が出る。**0x0A(セグメント 10)= ピンクパープル、0x0C(セグメント 12)=
   ピンクレッド**(左上から 1 と数えると 11 番目と 13 番目)、全色が約 7.3 秒でそろって終わる。
   **例外: 0x0B 黄緑(12 番目)は約 5 秒で色が出そろい、残り約 2 秒は見た目が変わらない** ― 故障ではない
   (Meris の波形が黄緑だけ最後まで同じ向きに押し続ける。FW_260923 ではさらに 0.7 秒早かった)。
   **本番のデザインでは黄緑を使わない**(運用者の決定 2026-11-19。Conductor で黄緑だけ開始を 2.1 秒遅らせる案を
   基板 03 で試したが、最後に少しちらつき、終わりも後ろにずれたので不採用)。色が違う・6 色なら FW_260923 のままで書けていない可能性が高い。4 へ戻って書き直す
8. **Conductor のショー**(掃引 0x1F の遅延つき)をこの機体に Upload → START。最後まで走ること。
   その後**電源を入れ直し**、autoplay と待機(白)が従来どおりか見る
9. 8 までが全部良いときだけ次へ。変なら止めて PM へ(§4 で戻せる)

## 5. 今後オペレーターが気づく違い

LCD は**全機 30 秒**で消える(`--blank-after 0` で無効)。UPDATE FW / CLEAR BOARD / GIT PULL / FW VERSION /
BOARD INFO / REBOOT / WIFI / SPEAKER の作業中は消えず、書き込み・消去・pull の結果とエラーは点灯して
**押すまで**点いたまま。暗い画面から止めるとき(短押しは点灯から 1.5 秒以内なら点灯扱い、長押しは
点いた画面で押し始めれば効く):

| 機体 | 暗い画面から止める |
|---|---|
| radxa-05(EXHIBITION) | 何か 1 つ押して点灯 → **KEY1 を長押し**(約 1.5 秒)= STOP |
| ガーメント機(パターン / PC ショー) | 押して点灯 → **約 1.5 秒待って KEY2** |

- すぐ KEY2 を押すと点灯扱いで何も起きない(保護)。2 度押しでは止まらない
- 同じ障害の再点灯は 1 分に 1 回まで
- **途中参加の注意**: ショーの途中で入った機体が遅れたキューを発火すると、直後に探りの STOP を送って
  最初の絵が途中で切れることがある(次のキューから正常。既知・未修正)
